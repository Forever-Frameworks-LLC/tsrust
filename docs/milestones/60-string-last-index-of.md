Status: complete. Four focused groups, one 597-group regression, required Rust checks and fresh O0/O3 release checks pass. Four default/bounded ASCII/Unicode comparisons across eight runtimes, 864 TypeScript observations, eighteen unique Node harness groups and twelve native allocation profiles complete acceptance. ## Native string contract

Support `string.lastIndexOf(needle, position?)` using standard Rust UTF-8 storage and substring search. Return the greatest matching byte offset at or before the selected position, or -1. Default to byte length; negative positions clamp to zero and positions beyond length clamp to length. The selected position must be a UTF-8 character boundary, even for an empty needle. Match-start position bounds must retain overlapping matches and must not truncate a match that begins at the selected position. Empty needles return the selected byte position.

Borrow receiver and needle throughout position evaluation; evaluate all operands once in source order. Preserve current temporary, field, indexed selection and closure ownership rules. Keep array reverse search unchanged. Native byte coordinates are deliberate; matched Unicode counterparts must translate JavaScript UTF-16 coordinates and include that translation cost in their measurements.

## Acceptance

Focused O0/O3 checks cover default and bounded positions, both signed extremes, empty receiver and needle, duplicates and overlaps, misses, ASCII, astral and combining Unicode, NUL, invalid selected boundaries and an internal endpoint inside an unrelated multi-byte character. Search allocation instrumentation and normal/unwind disposal checks pass. Three initial focused passes were retained while the failed ownership fixture was corrected and rerun; the full 597-group regression ran once.

Four matched comparisons separate default and bounded searches over ASCII and Unicode input. Every invocation retains all 2,048 byte indices as index + 1, including misses; subtracting one recovers every original result. The accepted int-array ABI and observer encode complete outputs outside timing. ASCII counterparts directly call actual JavaScript String.lastIndexOf because byte and UTF16 offsets coincide in that input domain. Unicode counterparts build standard TextEncoder scalar coordinate maps, translate selected byte positions to UTF16, call actual String.lastIndexOf and map the result back to bytes. Mapping setup and lookups are timed and remain part of the Unicode comparison.

Bounded rows use a dynamic valid-position pool from signed extremes, negative and zero positions, byte length and six fixed indexOf support searches. Misses clamp to zero; the first aa match plus one is a valid ASCII boundary. Both languages perform the same support searches once per invocation. Needle setup, query selection, searching and full output retention are timed; these measurements describe complete iterations. The first native preflight stopped before Rust compilation because a benchmark fixture tried to own an indexed borrowed needle. The four native kernels were corrected to pass that indexed needle directly as a borrowed search argument. The compiler and TypeScript counterparts were unchanged; completed counterpart checks and the failed native attempt were retained with the source supplement. Runtime input is valid Unicode with at most 256 UTF8 bytes, and ASCII rows require ASCII input. JavaScript rounding of extreme i64 literals leaves the same clamped position.

An independent UTF8 byte encoder and forward match scan retain the greatest eligible start, preserving overlaps and matches extending past the selected position. Actual source checks cover 864 cases, eighteen independent hand cells, ten valid and five invalid selected-boundary cells, nineteen mutation/domain/boundary negatives and complete evaluation-order output. Native preflight records eighteen O0/O3 builds, forty complete outputs, eight untimed allocation/disposal checks and two complete order outputs.

Timing records 96 process cells and 2,976 measured batches, publishing 32 min/average/max rate cells. Twelve allocation profiles retain raw counters and report min/average/max allocations, reallocations and requested, retained and peak bytes per operation across three samples. Input adaptation stays separate. Peak memory is the retained-batch peak divided by 2,048 operations, not an isolated-call peak. All live bytes reach zero after output and final disposal. All 346 earlier runtime tables, nine primitive memory tables and auxiliary startup/compiler baselines remain byte-exact; no earlier measurements were repeated.
