# Milestone 55: higher-order function values

[Roadmap](../roadmap.md) · [Declared function values](./54-declared-function-values.md)

## Scope

Extend declared function values to callback-consuming targets. Inferred local bindings must support every current reusable, once, owned and owned-once callback contract, mixed data/callback parameters, multiple callbacks and existing data families. An empty forwarding environment stays reusable even when an invocation consumes callback arguments.

Preserve actual result origins for resolved callable factories, returned owned callback parameters and closures capturing owned callbacks. Calls through one bound consumer with different concrete callback origins must produce independently typed results without changing the consumer binding's declared origin. Keep current moves, aliases, replacement, captures, loans and left-to-right evaluation.

Passing or returning a consumer under a nested callable annotation requires recursive callable parameter syntax and contracts. The source audit accepts this foundation as part of the full higher-order scope. Inferred bindings alone do not establish complete higher-order function-value support.

## Compiler dependencies

Reuse ordinary Rust static forwarding and the existing callback traits. Forwarding methods and adapters need generic callback witnesses with exact access modes and separate borrowed lifetimes. Bound calls must reuse declared-target specialization and returned-origin substitution, including owned templates and single-use adapters. Callback-instance analysis must include actual forwarding edges and concrete argument origins while retaining current depth and specialization guards.

The current callable parameter AST stores a named data type token. Both callback argument and result annotations need a recursive type representation and corresponding analyzer/emitter contracts; removing a parser restriction alone would not implement them. Argument-dependent factories also require origin-sensitive specialization when the outer consumer is borrowed. Pending-origin traversal and callback-instance analysis must cover nested contracts without collapsing equal signatures from distinct owners. No new erased runtime container, custom encoding or shared capture storage is proposed.

Higher-order inline arrows need invocation-body materialization too. Preserve their original source/context before analysis consumes the body; replay against ordered concrete callback witnesses while keeping the same environment identity, capture layout, access modes and lifetime limits. Store each call's method target and returned origin separately from its stable binding. Owned/once arrows returning callback arguments or captured factory results remain in scope, as do borrowed consumers with argument-dependent results. Static methods and typed method/function graph edges implement this without cloning runtime environments or erasing their types.
