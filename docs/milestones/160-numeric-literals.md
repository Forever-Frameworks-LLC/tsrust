# Gate 160: numeric literal separators and radix forms

Decimal whole, fractional and exponent digit sequences now accept underscores
between digits. Explicit binary, octal and hexadecimal prefixes support either
letter case and separators. Numeric spelling is preserved by formatting; malformed
positions, missing prefix digits and invalid radix digits produce syntax diagnostics.
BigInt and other numeric suffixes remain unsupported.

## Types and implementation

Whole literals keep signed i64 defaults. Contextual number values can use wider
whole magnitudes and retain IEEE binary64 rounding or infinity, without adding
implicit runtime int conversion. Negative minimum int remains exact. Source ranges
retain the original spelling, including prefixes and separators. Numeric strings
retain their existing conversion behavior.

Scanning and integer-spelling normalization live in separate inline-never helpers,
outside recursive parsing frames. Radix magnitudes normalize to exact decimal text
before existing contextual type checking. Decimal conversion stops growing after
400 digits, when the value is already above finite f64 range; a bounded overflow
spelling preserves number infinity and int range rejection. Scanning still validates
all input digits. This avoids imposing a lex-time integer bound on number contexts
and prevents unbounded quadratic conversion for huge radix inputs.

Editor tokenization shares the checked numeric range scanner. Numeric expression
facts supply actual inferred/contextual types; no separate radix type heuristic is
added. Real TextMate tokens cover complete supported numeric spellings. Installed
VS Code grammar was atomically refreshed after its exact previous bytes were saved.
