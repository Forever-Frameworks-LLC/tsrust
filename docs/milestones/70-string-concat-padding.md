# Milestone 70: string concatenation and padding methods

Status: complete. String.concat, padStart and padEnd pass compiler, editor, source, native and runtime/resource acceptance: 637 compiler groups, 652 workspace groups, ten comparisons and thirty disposed profiles.

## Scope

Implement `String.concat(...strings)`, `padStart(target: int, filler?: string)` and `padEnd(target: int, filler?: string)` across existing String expressions, including borrowed arguments, returned values, conditional temporaries and array/record fields. Concatenation accepts zero or more String arguments. Padding accepts one integer target and an optional String filler, defaulting to one space. Mixed-type coercion, Number targets, omitted targets and explicit undefined remain unsupported under existing strict typing.

Receiver and arguments evaluate once, left to right, even when the result needs no padding. They remain borrowed through result construction; later operands cannot move or mutate an earlier borrowed source. Results preserve the existing UTF-8 Cow contract. Real concatenation or padding constructs an independent owned buffer. Zero/all-empty concatenation and no-op padding use standard Cow::clone: static borrowed text remains safely borrowed, while owned receiver storage is copied independently. Existing owners remain reusable. No tracing runtime or new string representation is introduced.

Padding follows the existing byte-length contract. A target no greater than receiver byte length, including a negative target, returns a standard Cow clone. Empty filler also returns a standard Cow clone. Otherwise repeat filler bytes and append a prefix to reach exactly the requested byte length. Reject a final prefix that cuts a UTF-8 scalar, consistently with checked native byte slicing. Combining sequences are valid scalar boundaries, not grapheme boundaries. Validate lengths and the prefix before output allocation; use standard Rust checked arithmetic, string reservation and `push_str` without an oversized repeated intermediate or per-repeat heap allocation.

The JavaScript [concat](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.concat), [padStart](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.padstart) and [padEnd](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.padend) methods provide the familiar call syntax and counterpart behavior. JavaScript counts UTF-16 code units and permits coercion; native byte targets, boundary errors and owned-copy versus static-borrow costs are deliberate differences.

## Acceptance

Four focused O0/O3 groups cover byte semantics, all UTF-8 widths including FEFF and Chinese prefixes, combining sequences, NUL, extreme targets, once-only effects, strict types, arity, prior-operand loans, conditional temporary lifetimes, normal-stack diagnostics and normal/unwind disposal. Existing contextual Array.concat remains valid. Changed construction uses one checked fallible reservation. Static no-ops allocate no result buffer; nonempty owned no-ops copy independently. Invalid filler prefixes and capacity failures use clear source-byte diagnostics without an internal compiler panic or allocation abort.

Four actual focused commands retain three original passes. The affected group first needed an existing callback-call fixture correction and the pure clone type hint; its next failure was an authored negative that used unsupported scalar clone. The corrected exact group passes, followed by one affected-group augmentation for three-byte Unicode prefixes. Original failed commands and source bytes remain preserved. The sole full workspace regression passes all 637 compiler and fifteen additional workspace groups without a restart. Doctests, formatting, all-target Clippy, debug/release builds and fresh byte-identical CLI emissions pass; the saved Gate69 release rejects the methods. LSP completion, hover and signature help include all three methods; eight affected existing editor groups pass separately and are not counted twice. An independent 34-cell native hand fixture passes at O0/O3.

Source validation passes ten TypeScript programs, 1,370 complete-output cases, 48 independent hand cells, 166 mutation/domain negatives, ten semantic mutants, two Node groups and twenty-one order lines. Native preflight accepts forty-two O0/O3 builds, one hundred complete outputs, twenty disposal checks and two order executions. Source-only packaging failures and repairs remain bound by the final runtime proof; accepted source checks were not repeated for packaging.

Ten comparisons cover zero/variadic ASCII and Unicode concat, default directional padding and explicit ASCII/Unicode filler in both directions. Every method result is retained completely in String[]. The whole timed workload includes receiver/argument setup, dynamic selection, the actual JavaScript built-in or native method, loops and output construction/retention. Unicode JavaScript padding initializes validated byte/UTF-16 filler-prefix tuples during timed setup and selects an equivalent UTF-16 target per operation. This preserves common output values while disclosing mapping/setup cost; it performs no per-operation encoder allocation. Native byte-boundary failures remain separate correctness evidence. These comparisons do not claim isolated method latency, identical ownership/storage behavior or allocation parity. Complete observation is outside timing.

The execution-only run records 240 process cells, 7,440 measured batches and eighty min/average/max rate cells across eight runtimes. Native leads compiled Node on 5/10 rows and the fastest scripting runtime on 3/10. Average-rate ratios span 0.682–1.434× versus Node and 0.630–1.171× versus the fastest scripting runtime. These are whole-workload results, not a universal native-speed claim. Complete per-row rates remain in [BENCHMARKS.md](../../BENCHMARKS.md).

All thirty profiles return output and final owners to absolute zero. Raw counters and normalized min/average/max allocations, reallocations and requested/retained bytes per complete operation are retained across three 2,048-operation samples. Input adaptation stays separate. Peak means retained-batch peak divided by operations, not isolated-call peak. Static Cow sharing, owned receiver copies, changed-result construction and complete String[] storage have their natural measured costs; JavaScript allocation parity is not claimed.

The report contains 454 separately dated comparisons. Prior 444 measured sections, nine primitive memory tables and auxiliary baselines remain byte-exact and were not retimed; no combined 454-row run is claimed. The [compiler proof](../../benchmarks/runtime/diagnostics/2026-10-03T00-07-33-000Z-string-concat-padding-compiler-proof.json), [source proof](../../benchmarks/runtime/diagnostics/2026-10-02T23-57-28-000Z-string-concat-padding-source-validation.json) and [runtime/resource proof](../../benchmarks/runtime/diagnostics/2026-10-03T00-15-54-000Z-string-concat-padding-runtime-proof.json) retain actual commands, results, release/source identities and failed preparation records.

## Remaining separate work

Mixed-type coercion, Number padding targets, omitted targets and explicit undefined remain unsupported. Native UTF-8 byte targets and scalar-boundary rejection deliberately differ from JavaScript UTF-16 indexing; combining sequences are not treated as indivisible graphemes.
