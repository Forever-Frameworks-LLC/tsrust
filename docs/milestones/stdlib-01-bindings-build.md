# S05: standard-library bindings and native build integration

Status: accepted for the primitive bundled std:path binding/build contract on macOS with focused evidence. Callable imports/local values/adapters/returns are verified within existing language storage boundaries. Callable containers and structured generic/results remain S06 requirements. Runtime/frontend/build measurements are registered and pending the scheduled checkpoint; no Windows/Linux distribution acceptance is claimed. S04 remains open independently.

## Concrete increments

1. **Registry contract**: compiler-owned module/export identity, primitive argument/result types, argument access modes, optional arity, bundled backend symbol and deterministic required features. Empty imports select no features; repeated imports deduplicate; unknown modules/exports fail distinctly. Implemented in native_bindings.rs, with the selected std:path basename descriptor. The descriptor is not available to source programs yet.
2. **Checked import integration**: recognize explicit `import { basename as fileName } from "std:path";`; preserve binding/source spans and aliases; distinguish std identity from disk modules. Resolve through the registry, feed access/type/arity into normal checking and preserve local shadowing/private module rules. Unknown names need source-qualified diagnostics. No runtime lookup, package search, any type or network acquisition.
3. **Native operation**: basename(path: string, suffix?: string): string. Native platform path separator semantics; trailing separators ignored; optional case-sensitive suffix removal; borrowed unchanged inputs and independently owned result. Verify empty paths, separator-only roots, dot/dot-dot components, Unicode, trailing separators, suffix equality/nonmatch/case and platform-specific paths. Platform targets require their own execution evidence; a macOS pass cannot establish Windows behavior.
4. **Editor parity**: complete builtins.json behavior/arguments/defaults/errors/ownership/examples before operation acceptance; lookup/signature/parameter/completion/hover from public registry identity rather than independently inventing types. Compile and execute catalog examples through named std imports; installed-package hover/signature/completion and alias witnesses.
5. **Build selection and cache**: bundled path helper uses the pinned Rust backend without external packages. Select only referenced native features and preserve the direct rustc path for ordinary programs. Deterministic build identity includes source graph, backend release, selected feature set and binding ABI. Verify cold build, offline repeated build, changed source/feature invalidation, friendly missing/wrong-backend diagnostics and unchanged non-std outputs. External dependencies later require exact Cargo lock/version/features/license admission; no implicit downloads during check/build. The empty external dependency graph for path is not evidence of a tested external-package cache.
6. **Gate acceptance**: focused compiler/runtime/editor/installed CLI witnesses above; register equivalent path-operation and frontend/build selection workloads. Measurements remain pending at the next applicable checkpoint. Preserve existing passed regression records.

## Research and decisions

Reviewed 2026-10-03: [Node path API](https://nodejs.org/api/path.html#pathbasenamepath-suffix) specifies platform-dependent paths, ignored trailing separators and case-sensitive optional suffix removal. [Rust std::path](https://doc.rust-lang.org/std/path/index.html) provides native path handling, but the adapter must verify observable edge cases rather than assume a Rust method is interchangeable. Keep runtime reference versions/provenance here, not IntelliSense. No npm/Rust popularity ranking or broad std-library parity claim follows from this operation.

Primitive synchronous bindings are the initial registry surface. Generic/tagged results, callbacks, resource lifetimes, async suspension and thread transfer require their roadmap prerequisites; do not encode guessed ownership or erase unsupported shapes to strings. The monomorphic registry will evolve alongside checked IR and those gates.

## Bundled native artifact cache

native_cache.rs owns local artifact lookup/publication. CLI build/run still checks source and verifies the pinned backend, then reuses a valid artifact keyed by length-framed source graph identities/text, generated Rust, selected registry features, compiler version, full backend identity, OS/architecture, optimization, overflow policy and cache ABI. Hashed directory names are validated against exact identity bytes. Artifact checksums detect ordinary corruption. Completed artifacts publish through sibling staging directories; missing/invalid entries rebuild, and failed cache publication preserves the successful compiled result. An invalid entry can be retired and replaced. Failed cache-copy reuse falls back to compilation.

Default storage is working-directory target/tsrust-native; TSRUST_CACHE_DIR overrides it. No external dependency graph or network operation is involved. The cache is local trusted build state, not a security boundary; its checksum is not cryptographic. No automatic size limit/eviction is implemented yet. Clear it by removing the cache directory.

Thirty focused cache/project/formatter tests pass (native-cache-focused.log). Unit acceptance covers missing entries, exact identity checks, corruption detection/repair and repeated publication. ## Concurrent damaged-entry repair

Publication acquires an OS advisory lock per cache identity after completing its private staging artifact, then rechecks validity under the lock before retiring an invalid entry.
