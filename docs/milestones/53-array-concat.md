# Milestone 53: homogeneous array concatenation

[Roadmap](../roadmap.md) · [Array coverage](../feature-coverage.md)

## Scope

Add variadic `concat` using ordinary Rust Vec copying/extension and existing result containers. Receiver `R = T[]` retains its element type and rank. Each argument is exact R, contributing its elements in order, or exact T when T is not itself an array. Non-array elements include current primitive leaves and nominal records. Zero arguments still return a fresh independent array.

JavaScript spreads actual array arguments one level regardless of how TypeScript labels an overload. For nested arrays, accept same-rank arrays and reject a lower-rank array passed as a purported scalar element. For example, `[[1]].concat([[2,3]])` preserves rows; `[[1]].concat([2,3])` contributes scalar integers and violates the homogeneous row type. Wrap a nested element in an outer array to append it. Typed lower-rank empty arrays remain rejected; an empty literal argument receives the full receiver type and contributes no elements. See [ECMAScript concat](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.concat) and [IsConcatSpreadable](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-isconcatspreadable).

Evaluate the receiver and all arguments once, left to right, before copying. Preserve readonly receiver/owned-argument loans while later arguments execute; copied scalar arguments are evaluated snapshots. Repeated immutable aliases are valid. Number literals receive existing Number context; nonliteral integers require explicit conversion. Strings and nominal records remain atomic elements.

Use narrow expected-result context propagation for concat to support literal receivers with an annotated result or return type, including empty receivers and contextual Number literals. Other calls retain their existing behavior. Typed receiver/argument evidence takes precedence over incompatible result context; do not invent an element type when neither context nor arguments provide one.

Native copying creates independent owned descendants while JavaScript shares references. Compare content, shape, order and effects; disclose ownership costs and separately test native independence. Dynamic unions, sparse holes, coercion, species/subclasses, Symbol spreadability, array-like objects and source spread syntax remain separate capabilities.

## Acceptance

Focused checks at optimization levels 0 and 3 cover current primitive/record/rank families, zero/empty/variadic arguments, scalar-versus-array classification, nested wrapping/rejection, receiver/result context, temporary/field/indexed/fixed/literal sources, operand order, readonly conflicts, Number bits, Unicode/NUL contents, owned-copy independence, and disposal during normal or failed construction. Use one settled full regression after focused checks pass; retain passed suites if a repair is needed.

Matched TypeScript workloads use safe same-rank arrays and non-array scalar elements. Independent manual concatenation defines complete expected output contents and shape. Time actual whole-iteration concatenation separately from untimed allocation/disposal; disclose source/result copying and retention costs. Preserve previous records and retime only new or affected operations.
