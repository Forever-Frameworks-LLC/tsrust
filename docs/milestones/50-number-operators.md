# Milestone 50: Number bitwise operators and exponentiation

[Roadmap](../roadmap.md) · [Number coverage](../feature-coverage.md)

## Scope

Add Number operators `&`, `|`, `^`, `~`, `<<`, `>>`, `>>>`, and `**`. Operands and results use primitive `number`. These operators establish Number context for literals; nonliteral int, boolean and string operands require explicit conversion. Existing checked int arithmetic remains unchanged. BigInt, int bitwise extensions, compound assignments and update operators remain separate capabilities.

Use milestone 48's finite/truncated modulo-2^32 conversion and ordinary Rust u32/i32 operators. Shift counts use their low five bits. Signed results convert exactly to f64; unsigned right shift returns the unsigned value as f64. Exponentiation reuses milestone 49's small IEEE guards and standard `powf`, including its documented native precision differences. No new storage or custom numerical algorithm is required.

Evaluate operands once, left to right, before conversion or power guards. Preserve standard bitwise/shift precedence and right-associative exponentiation. Require parentheses around a unary exponentiation base while permitting negative exponents and grouped negative bases. Keep existing minimum-int literal handling and parser depth limits.

## Acceptance

Focused native checks at optimization levels 0 and 3 cover fractional conversion, NaN/infinities and signed zero, signed/unsigned boundaries, wrapped shifts, grouping and association, power classifications, argument effects, captures, record fields, numeric arrays and enclosing loans. Preserve existing diagnostics and depth checks; replace only unsupported cases that become supported. Run one settled full regression, retaining passed suites after any affected-case repair.

Each operator receives its actual TypeScript counterpart. Bitwise comparisons use independent integer/bit expectations; exponentiation uses independently generated numerical references and the established approximate protocol. Keep observed results, numerical error, throughput and allocation evidence separate. Do not replace actual power calls with exact special-answer-only workloads.
