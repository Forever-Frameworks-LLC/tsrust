# Milestone 51: array reduction

[Roadmap](../roadmap.md) · [Array coverage](../guides/language/feature-coverage.md)

## Scope

Add `reduce(callback, initial?)` and `reduceRight(callback, initial?)` across all existing dense array element types and ranks. Support named, field, indexed, temporary, and literal receivers through their ordinary existing storage. With an initial value, the accumulator may use any current data type independently of the element type: int, number, boolean, string, named record, or nested array. Without an initial value, the accumulator and callback result use the element type. Callable and void accumulators require separate contracts.

Support reusable typed inline arrows, named closures, and callback parameters with zero through four positional arguments: accumulator, current element, original int index, and readonly source. Callback results must match the accumulator type. Copy arguments copy; owned source elements and the source array remain readonly. The independent owned accumulator may be read, mutated, or consumed according to the existing callback parameter contract. Consuming an accumulator argument does not require consuming the callback environment.

Evaluate the receiver, callback expression, and optional initial expression once in source order. Preserve source loans, capture conflicts, and temporary lifetimes throughout traversal. Mutable captures of unrelated storage remain valid. Consuming callback environments remain invalid for repeated invocation.

Without an initial value, copy or clone the first element for forward reduction or the last element for reverse reduction, then skip that seed during callback visits. Empty input fails after receiver and callback evaluation. Singleton input returns its independent seed without invoking the callback. With an initial value, empty input returns that initial value unchanged; nonempty input visits every element. Reverse reduction preserves descending original indices.

Use an ordinary mutable accumulator and standard Rust iteration or indexed traversal. No new containers, per-iteration accumulator cloning, or custom memory representation are required. Native owned seeding and returned values can clone where JavaScript shares references; preserve this ownership contract and disclose its costs.

## Acceptance

Focused checks at O0 and O3 cover all current element and accumulator types, nested ranks, type-changing reductions, both directions, empty and singleton inputs, optional initial values, callback origins and arities, operand/capture order, loans, diagnostics, fixed-storage fallback, and disposal during success and failure. Run one settled full regression, retaining passed suites after any repair.

Compare both directions against actual TypeScript reductions with copied scalars and owned strings, records, and nested arrays. Include noncommutative accumulation, original-index traces, and complete result contents. Independent manual traversal supplies expectations. Integer domains remain exactly representable; number comparisons use bounded dyadic arithmetic with identical source order and exact IEEE observation. Measure whole-iteration throughput and allocation/disposal separately, disclosing native seeding, ownership, construction, and retention costs. Preserve previous records and repeat only affected operations.
