## Verified integration boundaries

analysis::resolve_value_type rejects Kind::Callable for field/value positions. resolve_array_annotation admits only current dense primitive/record families. Type::Closure identifies an environment origin; Type::Callback and Type::Callable are parameter/result contracts, and emitter rust_type treats the latter as unreachable storage. The current union arena rejects callable members. Record runtime and generated clone implementations assume existing cloneable leaf families. These are distinct boundaries; merely relaxing the annotation resolver would produce invalid native types and ownership behavior.

## Implementation gates

1. Introduce an isolated callable value contract interner using ordered concrete parameter types/access, result type and invocation contract. Retain source parameter names separately from structural identity. Existing origin/path callback IDs remain available for checking; do not merge ownership paths merely because their signatures match. Resolve structured callable field and array annotations through this interner, with normal source-depth limits and finite contract expansion. Keep unsupported storage rejected until gates 2–3 provide an actual checked/native path. Test identical shapes, distinct nominal children, nested callable contracts, once/reusable incompatibility and explicit source spans.
2. Add a checked storage type distinct from origin-specific Closure. A value carries its concrete callable contract and an eligible owned environment origin. Construction/conversion checks parameter/result/access compatibility through existing require_parameters/require logic and rejects borrowed captures. Record initialization, field assignment and field selection preserve provenance and ownership paths. In-place invocation must infer receiver mutation or consumption; taking a callable out must update partial-transfer state. Once invocation cannot leave a callable available. Replacing a consumed field restores only that path. First accept record fields with one origin and exact contract, retaining other storage forms as explicit pending gates.
3. Implement native storage and dispatch in an isolated emitter/runtime component. Prefer finite tagged enums of compiler-known environment origins per contract, preserving monomorphic singleton fast paths. Each variant owns its existing compiled environment; dispatch borrows, mutably borrows or consumes according to the checked contract. Recursive environment layouts require explicit indirection and layout checks; record/container edges must not silently create infinitely sized Rust types. Native function bridges become typed variants and retain registry identity/optional argument adaptation. If any shape needs boxing, record the allocation scope rather than claiming zero-cost storage. No unsafe global registry or arbitrary dynamic payload is acceptable.
4. Extend storage to mixed eligible origins and homogeneous arrays, including nested arrays. Different captures sharing a contract must remain independent. Indexed access borrows owned elements; extraction/removal returns ownership through existing container rules, while once in-place invocation invalidates the checked path. Account for dynamic indices, overlapping loans, array mutation and closure captures of container paths. Audit every existing array operation for the new leaf: length/index/iteration first, then copying/reordering/filtering/removal/reduction individually. Operations requiring clone must reject noncloneable callable leaves with precise diagnostics until an explicit clone contract exists. Record clone must likewise reject noncloneable fields instead of generating an invalid or implicit-sharing Clone implementation.
5. Complete editor/public metadata and release acceptance. Standalone and project callable fields/array elements expose concrete source signatures, parameter help, completion chains and original definitions. Preserve private/transitive nominal identity, unsaved changes and conflict suppression. Native O0/O3 witnesses cover read/mutate/consume invocation, mixed captures, nested replacement/extraction, early returns/drop, borrowed-capture rejection and use-after-consume. Include normal-stack depth and count witnesses. Register matched runtime/frontend workloads, disclose representation/boxing costs and queue measurements for the scheduled checkpoint; do not rerun the peer's full checkpoint during an implementation gate.

## Handoffs and sequencing

Contract interning and source validation can proceed independently of Node built-in additions. Broad Type/ArrayElement changes require an explicit finite audit of exhaustive matches in analysis, source substitution, unions, native bindings, emitter and record runtime before widening accepted source. New ArrayElement variants are not automatically supported by every built-in. Callable union storage is a separate acceptance task; this plan must retain it as pending until ownership/drop and emitted tagged layouts are verified.

Result<T,E> still needs a tagged payload representation, discriminant narrowing, construction/forwarding and early-return ownership. It must not depend on faking callable fields as ordinary records or dynamic values. Resources, JSON/schema validation, concurrency, HTTP/database/caches/queues remain required by the main roadmap after their existing gates.

No direct user decision is needed for these established ownership semantics. If the implementation requires changing clone behavior, callable invocation syntax or the approved native execution model, present the concrete choice before committing to it.

## Staged finite native dispatch component

Admission verifies owned environment eligibility, concrete/nonpolymorphic/non-template layout, zero capture lifetimes, parameter count/type/access and exact result type.
