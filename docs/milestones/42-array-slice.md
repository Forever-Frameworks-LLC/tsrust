# Milestone 42: owned array slicing

[Roadmap](../roadmap.md) · [Primitive coverage](../feature-coverage.md)

## Scope

Add array `slice()` with zero, one, or two int bounds for every currently supported element type and rank. Omitted start means zero; omitted end means length. Negative bounds count from the end and clamp to zero; positive bounds clamp to length. An end at or before start returns an empty array. Handle the full signed int range without overflow, including the minimum value.

Borrow the receiver once, evaluate bounds once from left to right, and preserve the source loan through bound evaluation. Return independent owned storage using ordinary Rust slices and existing element cloning. Keep string `slice` overloads and their UTF-8 byte-boundary rules unchanged. Existing move, capture, borrow, and fixed-array proof rules still apply.

Native owned elements use existing clone semantics. Nested arrays and records can therefore copy owned contents more deeply than JavaScript's shallow array slice. Document that distinction explicitly; this gate does not introduce shared object identity or a custom storage representation.

## Acceptance

Native tests run at optimization levels 0 and 3. Cover empty inputs, omitted bounds, every signed boundary, reversed bounds, temporary and borrowed receivers, source reuse, independent output mutation, existing element types and ranks, and diagnostics. Check bounds evaluation order and rejected source mutation during its loan. Verify fixed literal storage remains available where its existing proof permits it. Run one settled full regression after integration.

Matched comparisons include scalar, number, string, and nested-array workloads with independent value/order oracles. Clearly disclose native owned-copy costs and any JavaScript ownership adaptation; do not claim equivalent alias behavior for nested objects. Preserve actual timing, allocation, and disposal records and update the corresponding sections of BENCHMARKS.md.
