# Milestone 43: temporary array indexing

[Roadmap](../roadmap.md) · [Primitive coverage](../feature-coverage.md)

## Scope

Allow indexing an owned temporary array, including array literals, function results, and method results such as `values.slice(1)[0]`. Support existing scalar, string, nested-array, and record element types. Evaluate the receiver once, then the index once, and preserve native bounds-failure order.

Copy scalar results or transfer an owned element from temporary storage without cloning merely to bypass a lifetime restriction. Use standard Rust methods and existing containers. Keep the selected value alive through its consuming expression or borrowed call, and dispose of unselected temporary contents safely. Nested indexing and field projections must preserve the same ownership rules.

Named, field, and indexed storage paths retain their existing loans and restrictions on moving borrowed elements. Temporary indexing does not permit assigning into a disposable temporary target or mutating a borrowed receiver through index evaluation. Existing contextual array typing applies; unsupported untyped empty and record literals retain diagnostics.

## Acceptance

Focused native programs run at optimization levels 0 and 3. Cover receiver/index evaluation order, bounds failures, scalar copies, owned strings, nested arrays, records and recursive disposal, callbacks, borrowed arguments, and independent source reuse. Verify selected owned storage transfers without unnecessary cloning and existing named-element restrictions remain enforced. Run one settled full regression after integration.

Matched comparisons observe complete values and shapes for representative temporary indexing operations. Disclose receiver construction, selection, output retention, and native ownership costs. Retain immutable timing and allocation/disposal records and update BENCHMARKS.md.
