## Behavior

Declaration, function/arrow parameter, callback and for...of patterns accept default values. Defaults select only undefined, preserve null/false/zero/empty text, run lazily and initialize names from left to right. A missing array position, tuple position or fixed-record field can select a default. Nested patterns and renamed fields compose with defaults; the source is evaluated once. Whole parameter defaults compose with pattern defaults.

Parameter initialization includes the pattern before the next parameter default. Later defaults can read earlier destructured names; current/later names are unavailable. Nested arrow defaults retain their own parameter pattern prologue. Generic nullable element defaults preserve null during specialization.

Names follow source access. Readonly parameters and array elements lend, while owning record/tuple positions can move. Fresh fallback owners have persistent local storage for borrowed selections; no implicit clone occurs. Borrowed bindings retain lexical source loans even when absent. Overlapping fallback mutation and transfer of borrowed selections are rejected. See [the guide](../../website/src/content/docs/language/destructuring.md) for executable examples and errors. Rest copying still awaits the owner's decision; classic-for initializer patterns and optional record-field annotations remain unsupported.

## Implementation and evidence

The parser lowers an undefined-only default selection, stages nested pattern holders before their children and preserves direct source projections. The analyzer permits absence-aware array/tuple/record selection while validating source ownership. Native fallback owner declarations persist outside conditional selection and initialize only on the reached branch; nullable owners receive concrete union annotations. Parameter patterns are checked and emitted during parameter initialization while remaining in the checked body for other source walkers. Recursive dispatch delegates to non-inlined helpers.
