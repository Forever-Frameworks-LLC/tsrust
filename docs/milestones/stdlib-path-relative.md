# Relative path family acceptance

The bounded family adds only `std:path.relative(from: string, to: string): string`. It borrows both required string arguments, returns owned text and reports required cwd lookup or UTF-8 failures through checked native errors. [The contract](path-relative-contract.md) defines roots, Unicode, drive contexts and platform coverage. Main source, SQLite evidence and all five executable consumers are integrated. See the committed handoff.

Focused acceptance covers direct imports, aliases, stored calls, independent owned arguments/results, exact arity/types, deleted cwd, injected non-UTF-8 conversion and repeated native allocation balance after one-time entry initialization. All 248,832 independently observed POSIX/Windows reference pairs pass. IntelliSense includes completion, hover, both parameter labels, signatures and natively executed examples.

The imported factory witness initially loses the two-argument callable after a relative observer call. Registering the binding in the existing non-callback observer list restores independent point-sensitive factory state at O0/O3 and in editor signature help, while the separate runtime failure contract remains fallible. Shared changes are additive binding registration, native emission/error adaptation, error effects, observer metadata, catalog/tests and benchmark registrations.

Before reconciliation, complete compiler regression records 2,278 passes and the three known failures of the older main base; the additional optimized allocation witness passes separately. Complete LSP regression records 347 passes and no failures. All eight depth canaries pass. After reconciliation with scheduling checkpoint `a724dbc`, combined regressions pass 2,350 compiler tests and 362 LSP tests with zero failures; three compiler tests are intentionally ignored. The later empty Windows drive-context correction passes nine affected native/allocation tests and all reference pairs. Completed evidence is retained rather than discarded.

The matched `std_path_relative` workload has an independently spelled oracle, strict TypeScript checking, fallible native ABI support, source mutation guards, exact fingerprints, output observation and runner/profile hooks. Native and Node-after-tsc pass the unchanged five correctness cases. Execution-only timing uses three processes, eight warmups and 31 samples per process for each engine; allocation diagnosis keeps all three original samples and verifies zero live bytes after drop.

Original measurements and profiles remain immutable. POSIX resolution now uses two borrowed component buffers, one cwd observation and one reserved result. The injected allocation witness drops from 20 allocation events to four. Actual workload allocation diagnosis drops from 15 allocations and ten reallocations per operation to four allocations and one reallocation, plus retained-vector overhead. The earlier optimized cohort measures 0.166× Node-after-tsc. The integrated source cohort measures 0.183×, retaining the allocation reduction and zero live bytes after drop. The final cohort begins after regressions finish; the earlier concurrent cohort is preserved with its conditions. A stale isolated consumer profile is retained as rejected optimization evidence.

This is a cwd-inclusive complete workload, not isolated API latency. [Node's pinned cwd wrapper](https://github.com/nodejs/node/blob/v24.11.1/lib/internal/bootstrap/switches/does_own_process_state.js) caches cwd until `chdir`; native execution observes host cwd for each invocation to retain current-directory and lookup-failure behavior. No cache across invocations is introduced. No earlier workload is retimed. SQLite proofs `runtime/diagnostics/path-relative-original-proof.json` and `runtime/diagnostics/path-relative-final-proof.json`, plus current-source `runtime/diagnostics/path-relative-integrated-proof.json` retain raw records, source/tool identities and review.

Native execution is macOS ARM64. Windows is deterministic internal-helper/reference coverage, and non-UTF-8 filesystem execution is conditional on Linux support. This acceptance does not complete the whole path module, OS module or standard library.
