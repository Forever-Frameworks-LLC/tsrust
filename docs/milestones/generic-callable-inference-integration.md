## Concrete failure and intended behavior

`invoke<T>(action:owned (value:consume T)=>T,value:T):T` currently infers T from a typed data argument, but not from a checked callback plus `{name:'Pat'}`. The retained failure is target/editor/generic-owned-callback-contracts.log. Once implemented, a checked `(user:User):User=>{return user;}` binding must supply User to the parameter and result constraints, contextualize the record literal, and preserve nominal declaration identity. This must also work with explicitly selected type arguments; contradictory callback and data constraints must fail with precise source ranges.

## Isolated implementation gates

1. Add an analyzer-owned callable hint adapter alongside generic_calls.rs. Read already checked binding types only: Closure/Callable origins use their checked parameters and result, and Callback origins use callback_contracts. Preserve unknown/pending results as unknown. Do not call expression, invoke a callback, create a loan or transfer a binding while collecting hints. A borrowed capture remains borrowed; collecting type information does not grant owned eligibility. Initially unchecked inline arrows require a separate annotation-only path with ordinary later validation, not eager body checking.
2. Extend the shared generic_inference constraint input with optional callable data shapes, preserving its independence from analyzer state. A shape contains ordered optional checked parameter types and optional result type. Unify each known type against the corresponding structured callable annotation through the existing nominal/array/union solver. Validate arity. Grouped callable annotations must follow the same path. Parameter access, once/owned modifiers and invocation modes remain ordinary callback-checker requirements; inference cannot weaken them. Repeated T in input/output/data arguments must resolve to one checked identity.
3. Thread these hints through both Cache::parameter_contexts and Cache::infer, including every deferred nested-argument retry. Keep contextual record literals unknown until a nominal context exists. Use immutable checked snapshots; no generated-name parsing, new expression fields or whole-program clone. Expected result constraints and data/callable constraints must agree before publication. A missing generic variable still fails finitely.
4. Verify native O0/O3 behavior for the original failing literal case, typed data, repeated invocation, consuming callback arguments, returned owned mutable environments, explicit/implicit mixtures and nested calls. Negative witnesses cover conflicting nominal types, callback arity, wrong result type, insufficient information, borrowed captures passed as owned, once reuse and indexed owned arguments without clone. Confirm argument effects and callback invocation occur once, in source order, and retain the normal worker stack/depth guards.
5. Extend concrete generic-call metadata and editor adapters to display callable parameter/result contracts using original parameter names and ownership/access modifiers. Project facts need structured callable types and source-aware nominal children. Verify hover/help and result chains, private/transitive aliases, shared-span ambiguity and unsaved dependencies. Unknown shapes retain conservative source help. Register matched function runtime/frontend workloads and keep measurements pending checkpoint 96; copied CLI output and the broader S06 acceptance audit remain required.

## Dependencies and wait points

Production checking already owns callback contracts and closure environment identity; no node built-in gate is needed for steps 1–4. Callable storage in records/arrays still requires its own representation/emitter work. Checked callable result discovery may be pending during recursion; the adapter must honor that state rather than force discovery or treat an abstract shape as concrete. Compiler/editor ?? compatibility remains a separate handoff and must not be represented as passing by excluding its test.

Focused checks run after each implementation change. Preserve the original failed witnesses and successful prior suites. This plan authorizes no larger worker stack, full-checkpoint restart, runtime timing claim, source-diagnostic suppression or installed-extension update.
