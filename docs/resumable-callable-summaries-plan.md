1. Keep the nested independent-call budget red before implementation. Its source facts use n outer call sites plus one shared inner call site. Require no more than 2n+2 evaluations and 4n invocation visits at 8/32/64 calls. Retain finite-recursion, guard, failure and separate-factory controls. The source-span correction in the initial test is evidence, not a compiler defect.
2. Extract persistent body state into its own module: immutable graph, per-node partitions and pending completion values, work queue with duplicate suppression, accumulated call facts and normal/return/throw exits. Seed local bindings exactly as the current summary flow does. First prove a one-shot drive equals the current evaluator before enabling resumption. Keep the current path as a reference in test controls during this gate.
3. Record dependency coordinates for suspended calls: request identity, parent request, graph node and affected partition/input state. Requeue only the relevant node when a callee outcome or opacity changes. Resume the expression from its saved pre-node input, never from a partly mutated state. Multiple calls inside one expression may require reevaluating that expression, but must not repeat earlier statements. Do not assume all callee updates are infallible or final.
4. Preserve parameter entry separately. Defaults execute in order and can call or throw; rest packing and parameter-origin facts belong to the entry state. Cache only completed, dependency-valid entry preparation. A pending default must resume from its correct predecessor rather than reuse a partial frame. Capture environment updates and allocation record versions must invalidate affected cached inputs; immutable Request identity alone does not prove its environment facts unchanged.
5. Preserve recursive monotone fixpoints. Register dependency readers before suspension, including recursive cycles. Keep pending return values through finally cleanup, all exceptional edges and opaque propagation. Do not skip nominal/provenance canonicalization based on equality. Bound source arrays, partition widening and recursive allocation contexts using existing rules. No synchronous recursion over arbitrary callees, stack-limit increase or implicit clone is permitted.
6. Acceptance: make the nested budget green; verify body-driver equivalence, defaults/rest, capture updates, callbacks in arrays/records, exceptions/finally and recursive groups with native assertions and editor checks. Run eight depth canaries after shared flow changes. Compare emitted code for representative accepted workloads. Repeat the bounded large-workload diagnostic and only report throughput once an equivalent check completes. At the meaningful full scheduling milestone, reconcile complete compiler/editor regressions rather than restarting already completed evidence after each extraction. Preserve runtime measurements when emitted source is unchanged; reverify changed outputs before measurement claims.
7. Format the entire project before source checkpoints, stage explicit paths, preserve owner fixtures, import/read back exact SQLite evidence, refresh five consumers atomically from accepted source, prune closed artifacts and write a physical handoff.

## Integration boundaries

Do not allow worker acceptance to silently discard pending red scheduling witnesses or overwrite main evidence. This plan changes compile-time scheduling only; library APIs, public capture semantics and runtime behavior remain the existing contract.
