## Reproduce

Use the Node, Bun, and Rust versions in [versions.json](./versions.json), the workspace Rust pin, and the local locked dependencies. Version drift fails closed. All Node subprocesses use the harness's Node executable. No global package installation is required.

```sh
cd benchmarks/runtime
npm ci --cache /tmp/tsrust-npm-cache --no-audit --no-fund
npm test
node run.mjs --verify
node run.mjs
node profile-native.mjs
node allocations.mjs
```

If dependency installation defers package scripts, run `node node_modules/deno/install.cjs` and `node node_modules/esbuild/install.js`. Dependency setup needs network access; measurements use local files. tsx requires a local IPC socket. Compiler bootstrap uses `cargo build --release --offline`; emitted native programs use pinned rustc, edition 2024, optimization level 3, and overflow checks. Generated files stay in `target/runtime-comparisons`.

`--only=scalar_arrays` or comma-separated IDs select a separately recorded snapshot. `--verify` validates results without timed reporting. `--execution-only` prepares each program once, retains all five correctness cases on every engine and the usual 3 × 31 execution samples, but skips repeated startup/compilation measurements. The flags cannot be combined. New execution-only records contain empty auxiliary arrays and an explicit measurement scope; the report preserves separately dated auxiliary baselines, without inventing metrics for new workloads. True JSON records use exclusive creation. `node report.mjs` regenerates the report without executing workloads. Within one epoch, a partial run updates only measured rows; samples from separate runs are never merged. Results are grouped into numbers, booleans, strings, records/ownership, arrays, callbacks, recursion, and other controls. Primitive probes appear in their corresponding groups. The explicit mapping in report.mjs should be updated when adding operations; unknown measured IDs deliberately remain visible under Other. Unmeasured manifest entries never appear as measured rows. A new epoch starts with no measured rows and does not inherit earlier timings or resources.

Routine checkpoints use `--execution-only --engines=native,node-tsc --only=<workload IDs>` to compare native execution with compiled Node. `--engines` accepts unique known engine IDs and records the selected engines; invalid selections fail before building programs. Omission keeps the full eight-engine matrix. The subset keeps the same correctness cases, warmups, processes and samples per engine.

## Measurement and provenance

The first TSR function is `workload(n: int, seed: int)`, optionally followed by an external string and/or coordinate integer. [Adapters](./adapters.mjs) validate emitted signatures and add only argument and result hooks. They rename the source entry point and append [native](./driver.rs) or [TypeScript](./driver.ts) drivers without rewriting workload bodies. Inputs/results pass through native `black_box`; ordinary compiler optimization is allowed.

Specialization can place generated helpers before the workload. Ordinary native adapters select one function by its complete parameter and result signature, reject missing or ambiguous matches, and record that binding as `workloadABI`. Only appended driver calls use the selected generated name; authored workload bodies remain unchanged. Existing specialized observation protocols retain their own signature checks.

Correctness runs independently specified n/seed cases before measuring. Returned strings are hashed in order by Unicode scalar value, with a delimiter after every string, outside timers. Numeric workloads observe their numeric results; incidental string fields may be optimized away. Three fresh processes each perform eight warmups and 31 recorded batches per engine. Engines rotate through a deterministic order. Execution includes workload construction and returned values; checksum/reporting is excluded. Startup and frontend/check/compile phases are separately measured. The report computes each batch's ops/s, then its arithmetic mean; rounded figures do not justify tiny-gap claims.

Raw records include the semantic contract, machine, tool versions, commands, source/emission/instrumentation hashes, compiler inputs, driver/adapters/oracle/harness hashes, dependency lock, and samples. Background load and thermal state are not controlled. These comparisons make no HTTP, database, asynchronous, or tail-latency claims. Historical files retain their original semantics, source hashes, and measurement contracts; gains or regressions across changed contracts are not meaningful.

## Allocation measurements

Run native profiles and the primitive probes after timed processes finish. They count allocations, reallocations, requested storage, logical peak/live storage, and complete disposal. Native allocator storage and Node retained V8 heap are different metrics; empty control helps expose measurement overhead. The isolated forwarding allocator uses documented unsafe implementation requirements; compiler string storage uses standard Rust ownership.

`inputRequestedBytes` reports CLI input storage separately. Work counters start after input construction. `liveBytesAfterOutputDrop` reports the delta after disposing returned values while the input remains alive. `liveBytesAfterDrop` verifies disposal after the input owner also leaves scope. All current samples must return to zero. These counters do not measure physical copying, allocator overhead, RSS, or stack storage, and their execution is unsuitable for speed comparisons.

String search adds ASCII and Unicode rows for startsWith, endsWith, includes, and indexOf. Every iteration invokes one actual standard search, alternating the omitted-position default and a signed position clamped to the byte length. Query data uses valid scalar boundaries and empty, absent, repeated, combining, astral, and literal-NUL needles; no normalization occurs. Unicode Node counterparts prepare sparse byte-to-UTF-16 and UTF-16-to-byte maps once inside each workload call using scalar iteration and TextEncoder, then invoke the built-in search and translate only the position/result. Mapping and setup costs are included; no operation re-encodes the entire input. ASCII searches use equivalent byte/unit coordinates. These short-input results include observer and setup costs and do not isolate search alone. The independent oracle builds UTF-8 bytes arithmetically and matches sequences without any measured search API.
